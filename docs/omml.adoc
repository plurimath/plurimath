= OMML in Plurimath
:toc:

This page specifies the Office Math Markup Language (OMML) that Plurimath
reads and writes: how input is parsed, the shape of the output and its
options, how measurement results are hidden in a phantom, what does not
survive a round trip through Word or through Plurimath itself, the errors,
and the corpora that check all of this. It is part of the specification set
tracked in https://github.com/plurimath/plurimath/issues/525[#525].

The option table, the namespace table, the element tables, the examples and
the corpus counts on this page are generated (see <<regenerating>>). Each example is Ruby code that
the generator runs; the block after it is what that code returned. In OMML
examples the namespace declarations on `m:oMathPara`, which are the same for
every output and listed in <<writing>>, are shown as `xmlns:m="..." ...`.

[[reading]]
== Reading

`Plurimath::Math.parse(text, :omml)` hands the text to
`Plurimath::Omml::Parser`, which calls `::Omml.parse(text)` from the omml gem
and turns the typed model into a `Plurimath::Math::Formula` with
`Plurimath::Omml::Translator`. Both an `m:oMathPara` and a bare `m:oMath` are
accepted.

The text of an `m:r` run is read as text, except for numbers and function
names. A run that Word writes for a variable is therefore not an identifier
after reading. An `m:sty` style is kept as a font:

// BEGIN GENERATED example read-styled
[source,ruby]
----
Plurimath::Math.parse('<m:oMath xmlns:m="http://schemas.openxmlformats.org/officeDocument/2006/math"><m:r><m:rPr><m:sty m:val="i"/></m:rPr><m:t>x</m:t></m:r></m:oMath>', :omml).to_asciimath
----

[source]
----
ii("x")
----
// END GENERATED example read-styled

An element that the omml model does not know is dropped without an error:

// BEGIN GENERATED example read-unknown
[source,ruby]
----
Plurimath::Math.parse('<m:oMath xmlns:m="http://schemas.openxmlformats.org/officeDocument/2006/math"><m:foo/></m:oMath>', :omml).to_asciimath.inspect
----

[source]
----
""
----
// END GENERATED example read-unknown

An `m:oMathPara` inside an `m:oMath` or inside an argument is read as its
content, the same way as the outer `m:oMathPara`:

// BEGIN GENERATED example read-nested-para
[source,ruby]
----
Plurimath::Math.parse('<m:oMath xmlns:m="http://schemas.openxmlformats.org/officeDocument/2006/math"><m:sSup><m:e><m:oMathPara><m:oMath><m:r><m:t>x</m:t></m:r></m:oMath></m:oMathPara></m:e><m:sup><m:r><m:t>2</m:t></m:r></m:sup></m:sSup></m:oMath>', :omml).to_asciimath
----

[source]
----
"x"^(2)
----
// END GENERATED example read-nested-para

The translator raises `Plurimath::Omml::UnsupportedNodeError` for a model
node it has no rule for; `Plurimath::Math.parse` reports it as a
`ParseError` (see <<errors>>). The omml model reads the WordprocessingML
elements below in the `m:` namespace, and Plurimath has no node for them, so
they are refused there. Written with the `w:` prefix, the model does not
know them, and they are dropped like any unknown element.

* Inside `m:oMath` or an argument: the revision containers `m:ins`,
  `m:del`, `m:moveFrom` and `m:moveTo`, and the range markers
  `m:bookmarkStart`, `m:bookmarkEnd`, `m:commentRangeStart`,
  `m:commentRangeEnd`, `m:moveFromRangeStart`, `m:moveFromRangeEnd`,
  `m:moveToRangeStart`, `m:moveToRangeEnd`, `m:permStart`, `m:permEnd`,
  `m:proofErr`, and the `m:customXml...RangeStart` and
  `m:customXml...RangeEnd` elements.
* Inside `m:r`: `m:sym`, `m:ptab`, `m:fldChar`, `m:footnoteReference`,
  `m:endnoteReference`, `m:commentReference`, `m:object`, `m:pict`,
  `m:drawing` and `m:ruby`.

`Plurimath::Math::Formula#to_omml` in `lib/plurimath/math/formula.rb` takes these keyword options:

[cols="1,1"]
|===
|Option |Default

|`display_style:` |`displaystyle`
|`split_on_linebreak:` |`false`
|`formatter:` |`nil`
|`unitsml:` |`{}`
|===
// END GENERATED writer-options

* `display_style:` defaults to the display style the formula was read with.
  It decides how limits are placed: under and over the operator in display
  style, as scripts otherwise (see the two `lim` examples).
* `split_on_linebreak:` writes one `m:oMath` per line of the formula, with an
  `m:r` holding a `br` element between them, inside the same `m:oMathPara`.
  The `br` has no namespace prefix (it is not `w:br`), as the example
  shows.
* `formatter:` and `unitsml:` work as for MathML (see
  link:mathml.adoc#writing[MathML in Plurimath]).

properties:

[[uncertainty]]
== Measurement uncertainty

OMML has no attribute for meaning, so a measurement result is an `m:box`
whose `m:e` starts with a hidden, zero-size `m:phant` holding the marker
text. The visible content follows in the same `m:e`, and a unit is the one
inner `m:box` after the phantom. The
marker grammar and the reading rules are in
link:uncertainty.adoc#markers[Measurement uncertainty].

// BEGIN GENERATED example uncertainty
[source,ruby]
----
Plurimath::Math.parse("ustd(1.230, 0.004)", :asciimath).to_omml
----

[source,xml]
----
<m:oMathPara xmlns:m="..." ...>
  <m:oMath>
    <m:box>
      <m:e>
        <m:phant>
          <m:phantPr>
            <m:show m:val="off"/>
            <m:zeroWid m:val="on"/>
            <m:zeroAsc m:val="on"/>
            <m:zeroDesc m:val="on"/>
          </m:phantPr>
          <m:e>
            <m:r>
              <m:rPr>
                <m:sty m:val="p"/>
              </m:rPr>
              <m:t>standard-uncertainty(1.230,0.004)</m:t>
            </m:r>
          </m:e>
        </m:phant>
        <m:r>
          <m:t>1.230</m:t>
        </m:r>
        <m:d>
          <m:dPr>
            <m:begChr m:val="("/>
            <m:sepChr m:val=""/>
            <m:endChr m:val=")"/>
          </m:dPr>
          <m:e>
            <m:r>
              <m:t>0.004</m:t>
            </m:r>
          </m:e>
        </m:d>
      </m:e>
    </m:box>
  </m:oMath>
</m:oMathPara>
----
// END GENERATED example uncertainty

A phantom counts as a marker only when its `m:show` value is `off`, `0` or
`false`. A hidden phantom whose runs spell a marker but that also holds
anything other than `m:r` runs, or a box with more than one inner `m:box`,
raises `Plurimath::Errors::InvalidUncertainty` in the reader, which reaches
the caller of `Plurimath::Math.parse` as a `Plurimath::Math::ParseError`.

[[round-trip]]
== Round trips and Word

* Plurimath writes identifiers as plain `m:r` runs and reads plain runs as
  text, so a formula written to OMML and read back is not `==` to the
  original: its identifiers have become text. Numbers and function names come
  back unchanged.
+
// BEGIN GENERATED example readback
[source,ruby]
----
Plurimath::Math.parse(Plurimath::Math.parse("x^2 + 2", :asciimath).to_omml, :omml).to_asciimath
----

[source]
----
"x"^(2) + 2
----
// END GENERATED example readback
* The uncertainty marker is the exception. A result written and read back is
  `==` to the original, except that its unit comes back as the rendered
  formula (see link:uncertainty.adoc#round-trip[the round-trip matrix]).
* An OMML consumer that ignores hidden phantoms shows the marker text as
  ordinary text. Whether Word keeps the phantom when the equation is edited,
  and how it displays it, has not been tested (#524).

[[errors]]
== Errors

`Plurimath::Math.parse(text, :omml)` raises `Plurimath::Math::ParseError`
when the XML cannot be parsed, the omml model rejects it, or the translator
meets a node it does not support. The original error is not kept as the
`cause`. OMML takes no parse options; passing `locale:` raises
`Plurimath::Math::ParseOptionError`.
