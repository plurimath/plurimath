= Independent-input uncertainty propagation

`Plurimath::Math::Evaluation::Gum` accepts explicit estimates, component
variances and analytic sensitivity coefficients in one coherent unit system.
`analyze` derives exact first, second and third derivatives of an existing
Formula with polynomial/rational arithmetic and integer powers. It reuses
the existing expression parser. Unsupported function derivatives are refused;
there is no finite-difference Hessian fallback. Neither entrypoint infers
units or independence.

[source,ruby]
----
gum = Plurimath::Math::Evaluation::Gum
component = gum.component(distribution: :rectangular, half_width: "0.3")
result = gum.propagate(estimate: "12.3", components: [component],
                       gradient: [1], independent: true, guard_digits: 30)
result[:variance] # => (3/100)
result[:standard_uncertainty] # BigDecimal, declared precision
----

Inputs accept integers, rationals, decimal strings and finite BigDecimal
values. Binary Float input is refused. `type_a(observations)` reports count,
mean, extrema, sample variance, variance of the mean and degrees of freedom.
A rectangular, triangular or arcsine component takes a half-width. Curvilinear trapezoid additionally takes
`boundary_half_width: d`, with `0 < d < half_width`, giving variance
`half_width^2/3 + d^2/9` (JCGM 101 6.4.3.4); a normal
component takes a standard uncertainty. Student-t takes its scale and degrees
of freedom, giving variance `scale^2 * nu/(nu-2)`; `nu <= 2` is refused.

First-order propagation gives the sum of squared sensitivities times input
variances. Optional positive component degrees of freedom give the
Welch-Satterthwaite effective degrees of freedom. An omitted value denotes
infinite degrees of freedom; a returned nil means the denominator is zero.
This does not choose a coverage factor or assess LPU adequacy.

For `order: 2`, all components must explicitly declare `distribution: :normal`.
Supply a complete symmetric `hessian` matrix and `third` rank-three tensor,
plus `derivatives_complete: true`. The estimate includes half the diagonal
Hessian contraction. The variance includes both the Hessian-square and
first-times-third derivative terms in JCGM 100:2008 5.1.2 note. A Hessian
alone is insufficient: `f(x)=x+x^3` at zero has a zero Hessian and a nonzero
order-four variance correction. Every derivative entry, including zeros,
must be supplied. Unsupported joint dependence, nonnormal GUF2, incomplete
derivatives and negative approximated variance raise a named error.

[source,ruby]
----
formula = Plurimath::Math.parse("x+x^3", :asciimath)
result = gum.analyze(formula, estimates: { x: 0 },
                     components: { x: { variance: "0.01", distribution: :normal } },
                     independent: true, order: 2, guard_digits: 40)
result[:variance] # => (53/5000), including the first-times-third term
----

The estimate and component hashes must have identical ordered variable keys.
Results identify the engine version and method revision. They retain exact
rational variances and BigDecimal standard uncertainties; this is a Ruby API,
not the complete serialized cross-runtime evaluator contract.

== H.1 conventions and verification

The fixture records four distinct source conventions: rounded GUM 100 H.1
standard uncertainties, unrounded H.1 source components, JCGM 101 Table 10
PDF population moments, and GUM 5:2026 Table 8.1 PDF population moments.
These are different inputs and produce different uncertainties. The tests
use explicitly synthetic independent normal inputs with each variance set
to check the Taylor contraction; they refuse the actual nonnormal H.1 PDFs.
No assertion forces the original 34 nm result to equal the amended 36 nm
result within 0.5 nm. A special multi-affine moment identity does not remove
the general normality restriction.

Run `python3 spec/support/gum_h1_reference.py` to regenerate the exact
rational derivative fixtures and independently factored variance references.
The focused spec also checks a polynomial with nonzero third derivatives,
a quadratic with a nonzero mean correction and the refusal boundaries.

Sources: https://www.bipm.org/documents/20126/2071204/JCGM_100_2008_E.pdf[JCGM 100:2008],
https://www.bipm.org/documents/20126/2071204/JCGM_101_2008_E.pdf[JCGM 101:2008],
and the BIPM JCGM publications for GUM 100:2008/Amd.1:2026 and GUM 5:2026.

This entrypoint supplies numerical propagation, not a complete JCGM engine.
Unsupported function derivatives, unit-aware formula propagation, correlated inputs,
coverage intervals, adaptive Monte Carlo and conformance decisions remain
outside this API. `adequacy: :not_assessed` is always explicit.

== Quantity arithmetic

`Formula#evaluate_quantity(bindings)` is an explicit arithmetic entrypoint.
It needs UnitsML Quantity/conversion support (available in 0.6.14). Older
UnitsML versions retain the ordinary numeric evaluator; a quantity request
receives a named unsupported-expression error when that engine is absent.
Construct bindings with `Unitsml::Quantity.new(value: ..., unit: ...)`.
Numeric bindings and literals are dimensionless; integer division retains
rational magnitudes. Unit parsing, dimensions, composition, conversion and
scale legality stay in UnitsML. Addition and subtraction convert the right
operand into the left operand's unit before delegating the operation.

[source,ruby]
----
require "unitsml"
formula = Plurimath::Math.parse("x+y", :asciimath)
outcome = formula.evaluate_quantity(
  x: Unitsml::Quantity.new(value: 1, unit: "m"),
  y: Unitsml::Quantity.new(value: 50, unit: "cm")
)
outcome.value.value # => (3/2)
outcome.value.norm_text # => "m"
----

The supported expression subset is arithmetic, rational fractions, parentheses
and integer powers. Other functions raise an evaluator unsupported-expression
error. Dimension mismatches, conversion failures and invalid scale operations
preserve UnitsML's named error types. This does not attach units to GUM
sensitivities automatically; callers of Gum still supply one coherent system.

Quantity results expose `accuracy`; limited Float or BigDecimal sources remain
limited even when UnitsML conversion returns a Rational magnitude.
