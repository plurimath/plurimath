= Display-tree helper staging

Refs https://github.com/plurimath/plurimath/issues/537[#537].

The display-tree field printers and spacing/filtering helpers on `Math::Core`
load from `Core::TreeHelpers` on first helper use. `Math::ModelHelper` loads its
tree validation, filtering and private text helpers from its own `TreeHelpers`
module. Parsing, ordinary conversion, intent output, left/right validation and
notation masks leave both modules unloaded. Public method signatures, private
helper visibility, repeated calls and subclass `super` behavior are preserved.

`spec/plurimath/math/lazy_tree_helpers_spec.rb` checks the boundary in fresh Ox
and Oga processes. Existing `model_helper_spec.rb` checks the helper behavior.
The focused eight-input, six-writer probe against the parent change
`1dc34786093a8ad60f86a34d6ea8c4dc99590aa3` preserves 96 ordinary outputs,
16 intent outputs and 106 successful display outputs across both engines.
Two pre-existing display errors are unchanged. It loads 4,340 fewer bytes of
plurimath source through ordinary and intent conversion with either engine.
The cold `require "plurimath"` file list and source bytes are unchanged.
These are source-loading measurements; they do not establish time or memory
savings. Specialized node tree methods remain in their existing files.
