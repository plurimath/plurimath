= MathML in Plurimath
:toc:

This page specifies the MathML that Plurimath reads and writes: how input is
parsed, the shape of the output and its options, the `intent` attributes it
writes, how measurement results and units are carried, what does not survive
a round trip, the errors, and the corpora that check all of this. It is part
of the specification set tracked in
https://github.com/plurimath/plurimath/issues/525[#525].

The option table, the element tables, the examples and the corpus counts on
this page are generated (see <<regenerating>>). Each example is Ruby code that the generator
runs; the block after it is what that code returned.

[[reading]]
== Reading

`Plurimath::Math.parse(text, :mathml)` hands the text to
`Plurimath::Mathml::Parser`, which calls
`Mml.parse(text, version: 4, namespace_exist: ...)` from the mml gem and
turns the resulting MathML 4 model into a `Plurimath::Math::Formula` with
`Plurimath::Mathml::Translator`. `namespace_exist` is true when the first tag
of the text carries an `xmlns=` attribute. The XML itself is parsed by the
selected XML engine (see the "XML engines" section of the README).

Input without a namespace declaration, and input with a prefixed MathML
namespace, are both accepted:

// BEGIN GENERATED example read-no-namespace
[source,ruby]
----
Plurimath::Math.parse('<math><mi>x</mi><mo>+</mo><mn>1</mn></math>', :mathml).to_asciimath
----

[source]
----
x + 1
----
// END GENERATED example read-no-namespace

// BEGIN GENERATED example read-prefixed
[source,ruby]
----
Plurimath::Math.parse('<mml:math xmlns:mml="http://www.w3.org/1998/Math/MathML"><mml:mi>x</mml:mi></mml:math>', :mathml).to_asciimath
----

[source]
----
x
----
// END GENERATED example read-prefixed

The mml model keeps elements that MathML 4 deprecates, so `mfenced` is still
read, as its brackets:

// BEGIN GENERATED example read-mfenced
[source,ruby]
----
Plurimath::Math.parse('<math><mfenced><mi>x</mi></mfenced></math>', :mathml).to_asciimath
----

[source]
----
(x)
----
// END GENERATED example read-mfenced

The `display` attribute of the input is not kept. The output is always a
block (see <<writing>>):

// BEGIN GENERATED example read-inline
[source,ruby]
----
Plurimath::Math.parse('<math display="inline"><mi>x</mi></math>', :mathml).to_mathml
----

[source,xml]
----
<math xmlns="http://www.w3.org/1998/Math/MathML" display="block">
  <mstyle displaystyle="true">
    <mi>x</mi>
  </mstyle>
</math>
----
// END GENERATED example read-inline

An element that the mml model does not know is dropped without an error, so
it can disappear from the output. An element that the model knows but the
translator has no rule for, such as any Content MathML element, is refused
(see <<elements>>):

// BEGIN GENERATED example read-unknown
[source,ruby]
----
Plurimath::Math.parse('<math><foo>x</foo></math>', :mathml).to_asciimath.inspect
----

[source]
----
""
----
// END GENERATED example read-unknown

// BEGIN GENERATED example read-no-rule
[source,ruby]
----
Plurimath::Math.parse('<math><apply><ci>x</ci></apply></math>', :mathml)
----

[source]
----
raises Plurimath::Math::ParseError
----
// END GENERATED example read-no-rule

An `maction` element is read as the one child it shows, following MathML 3
section 3.7.1. That is the child that `selection` numbers, counting from 1.
When `selection` is missing or does not name a child, the first child is
read. The other children and the action itself are not kept:

// BEGIN GENERATED example read-maction
[source,ruby]
----
Plurimath::Math.parse('<math><maction actiontype="toggle" selection="2"><mi>x</mi><mi>y</mi></maction></math>', :mathml).to_asciimath
----

[source]
----
y
----
// END GENERATED example read-maction

The `intent` attributes of the input are not kept either. Intent output is
regenerated from the node classes, so it can differ from what was read:

// BEGIN GENERATED example intent-read
[source,ruby]
----
Plurimath::Math.parse('<math><mrow intent="absolute-value(x)"><mo>|</mo><mi>x</mi><mo>|</mo></mrow></math>', :mathml).to_mathml(intent: true)
----

[source,xml]
----
<math xmlns="http://www.w3.org/1998/Math/MathML" display="block">
  <mstyle displaystyle="true">
    <mrow intent=":fenced">
      <mo>|</mo>
      <mi>x</mi>
      <mo>|</mo>
    </mrow>
  </mstyle>
</math>
----
// END GENERATED example intent-read

An `intent` attribute that holds an uncertainty marker is the exception; it is
read as described in <<uncertainty>>.

[[writing]]
== Writing

`Formula#to_mathml` returns one `math` element in the MathML namespace with
`display="block"`, holding one `mstyle` whose `displaystyle` attribute is set
from the `display_style:` option. The output is indented by two spaces.

// BEGIN GENERATED writer-options
`Plurimath::Math::Formula#to_mathml` in `lib/plurimath/math/formula.rb` takes these keyword options:

[cols="1,1"]
|===
|Option |Default

|`intent:` |`false`
|`formatter:` |`nil`
|`unitsml:` |`{}`
|`split_on_linebreak:` |`false`
|`display_style:` |`displaystyle`
|`unary_function_spacing:` |`true`
|===
// END GENERATED writer-options

* `display_style:` defaults to the display style the formula was read with;
  it only changes the `mstyle` attribute.
* `intent:` adds `intent` attributes (see <<intent>>).
* `split_on_linebreak:` writes one `math` element per line of the formula
  instead of one element with a line break, joined with no separator. The
  `unitsml:` option is not passed on to the lines.
* `formatter:` is a number formatter (see "Number formatting" in the README).
* `unitsml:` is passed to the UnitsML renderer (see
  link:unitsml.adoc[UnitsML in Plurimath]).
* `unary_function_spacing:` set to false leaves out the empty
  `<mo rspace="thickmathspace"/>` that is otherwise written before a unary
  function such as `sin` when it follows another term (see the last two
  examples).

// BEGIN GENERATED example write
[source,ruby]
----
Plurimath::Math.parse("x^2", :asciimath).to_mathml
----

[source,xml]
----
<math xmlns="http://www.w3.org/1998/Math/MathML" display="block">
  <mstyle displaystyle="true">
    <msup>
      <mi>x</mi>
      <mn>2</mn>
    </msup>
  </mstyle>
</math>
----
// END GENERATED example write

// BEGIN GENERATED example write-inline
[source,ruby]
----
Plurimath::Math.parse("x^2", :asciimath).to_mathml(display_style: false)
----

[source,xml]
----
<math xmlns="http://www.w3.org/1998/Math/MathML" display="block">
  <mstyle displaystyle="false">
    <msup>
      <mi>x</mi>
      <mn>2</mn>
    </msup>
  </mstyle>
</math>
----
// END GENERATED example write-inline

// BEGIN GENERATED example linebreak
[source,ruby]
----
Plurimath::Math.parse("a = b \\\\ c = d", :latex).to_mathml(split_on_linebreak: true)
----

[source,xml]
----
<math xmlns="http://www.w3.org/1998/Math/MathML" display="block">
  <mstyle displaystyle="true">
    <mi>a</mi>
    <mo>=</mo>
    <mi>b</mi>
  </mstyle>
</math>
<math xmlns="http://www.w3.org/1998/Math/MathML" display="block">
  <mstyle displaystyle="true">
    <mi>c</mi>
    <mo>=</mo>
    <mi>d</mi>
  </mstyle>
</math>
----
// END GENERATED example linebreak

// BEGIN GENERATED example unary-spacing
[source,ruby]
----
Plurimath::Math.parse("2 sin x", :asciimath).to_mathml
----

[source,xml]
----
<math xmlns="http://www.w3.org/1998/Math/MathML" display="block">
  <mstyle displaystyle="true">
    <mn>2</mn>
    <mrow>
      <mo rspace="thickmathspace"/>
      <mrow>
        <mi>sin</mi>
        <mi>x</mi>
      </mrow>
    </mrow>
  </mstyle>
</math>
----
// END GENERATED example unary-spacing

// BEGIN GENERATED example unary-spacing-off
[source,ruby]
----
Plurimath::Math.parse("2 sin x", :asciimath).to_mathml(unary_function_spacing: false)
----

[source,xml]
----
<math xmlns="http://www.w3.org/1998/Math/MathML" display="block">
  <mstyle displaystyle="true">
    <mn>2</mn>
    <mrow>
      <mi>sin</mi>
      <mi>x</mi>
    </mrow>
  </mstyle>
</math>
----
// END GENERATED example unary-spacing-off

[[intent]]
=== Intent

With `intent: true` Plurimath adds MathML 4 `intent` attributes to the node
classes listed in link:../intent_supported_classes.adoc[intent supported
classes], which `rake intent_supported_classes.adoc` generates from the code.
An intent can name its arguments, and the elements that hold them get a
matching `arg` attribute:

// BEGIN GENERATED example intent-abs
[source,ruby]
----
Plurimath::Math.parse("abs(x)", :asciimath).to_mathml(intent: true)
----

[source,xml]
----
<math xmlns="http://www.w3.org/1998/Math/MathML" display="block">
  <mstyle displaystyle="true">
    <mrow intent="absolute-value(x)">
      <mo>|</mo>
      <mi>x</mi>
      <mo>|</mo>
    </mrow>
  </mstyle>
</math>
----
// END GENERATED example intent-abs

// BEGIN GENERATED example intent-sum
[source,ruby]
----
Plurimath::Math.parse("sum_(i=1)^n i", :asciimath).to_mathml(intent: true)
----

[source,xml]
----
<math xmlns="http://www.w3.org/1998/Math/MathML" display="block">
  <mstyle displaystyle="true">
    <mrow intent=":sum($l,n,$naryand)">
      <munderover>
        <mo>&#x2211;</mo>
        <mrow arg="l">
          <mi>i</mi>
          <mo>=</mo>
          <mn>1</mn>
        </mrow>
        <mi>n</mi>
      </munderover>
      <mrow arg="naryand">
        <mi>i</mi>
      </mrow>
    </mrow>
  </mstyle>
</math>
----
// END GENERATED example intent-sum

[[uncertainty]]
== Measurement uncertainty

A measurement result is written as an `mrow` whose `intent` is the
uncertainty marker, whatever the `intent:` option is, because the marker
carries data and not only a speech hint. Its unit is an `mrow arg="unit"`
inside it. The marker grammar, the three categories and the reading rules are
specified in link:uncertainty.adoc#markers[Measurement uncertainty].

// BEGIN GENERATED example uncertainty
[source,ruby]
----
Plurimath::Math.parse("ustd(1.230, 0.004)", :asciimath).to_mathml
----

[source,xml]
----
<math xmlns="http://www.w3.org/1998/Math/MathML" display="block">
  <mstyle displaystyle="true">
    <mrow intent="standard-uncertainty(1.230,0.004)">
      <mn>1.230</mn>
      <mrow>
        <mo>(</mo>
        <mn>0.004</mn>
        <mo>)</mo>
      </mrow>
    </mrow>
  </mstyle>
</math>
----
// END GENERATED example uncertainty

On reading, the marker and the unit are used and the visible content is
regenerated. A text that starts with one of the three marker names but does
not match the grammar raises `Plurimath::Errors::InvalidUncertainty` in the
reader, which reaches the caller of `Plurimath::Math.parse` as a
`Plurimath::Math::ParseError`.

=== MathML 4 conformance notes

* The writer emits presentation elements, with `intent` and `arg`
  attributes from MathML 4 when asked. `semantics` is written only when the
  formula was read from MathML that had one.
* The uncertainty marker follows our reading of the MathML 4 intent grammar
  (section 5.1). It has not been checked with a MathML 4 validator or a
  screen reader (#524).
* The output always has `display="block"` and an `mstyle` with
  `displaystyle`; inline layout is expressed only through `displaystyle`.

[[round-trip]]
== Round trips

Reading Plurimath's own MathML gives back the formula that was written,
except for what the reader drops: the input `display` attribute, unknown
elements, and `intent` attributes other than an uncertainty marker. Units read
from MathML come back as their rendered formula, not as a UnitsML node (see
link:uncertainty.adoc#round-trip[the round-trip matrix]).

[[errors]]
== Errors

`Plurimath::Math.parse(text, :mathml)` raises
`Plurimath::Math::ParseError` when the XML cannot be parsed or the model
cannot be translated; the original error is not kept as the `cause`:

// BEGIN GENERATED example read-malformed
[source,ruby]
----
Plurimath::Math.parse('<math><mi>x</math>', :mathml)
----

[source]
----
raises Plurimath::Math::ParseError
----
// END GENERATED example read-malformed

MathML takes no parse options. Passing `locale:` raises
`Plurimath::Math::ParseOptionError`:

// BEGIN GENERATED example read-locale
[source,ruby]
----
Plurimath::Math.parse('<math><mn>1</mn></math>', :mathml, locale: :de)
----

[source]
----
raises Plurimath::Math::ParseOptionError
----
// END GENERATED example read-locale

[[regenerating]]
== Regenerating this page

The regions between `// BEGIN GENERATED` and `// END GENERATED` comments are
written by `scripts/docs/format_specs.rb`, which also writes the other format
pages. Do not edit them by hand. From the Plurimath checkout, with the
testsuite submodule checked out:

[source,sh]
----
bundle exec ruby scripts/docs/format_specs.rb
----

The script runs each example and each row of the construct tables with the
code and bundle of the checkout, reads the option table from the source of
`Formula#to_mathml` and the element tables from the translators and the mml
and omml models, and counts corpus
cases at the testsuite commit recorded for `submodules/plurimath-testsuite`.
`--testsuite PATH` reads that commit from another clone of
plurimath-testsuite instead. Add `--check` to verify the pages without
changing them; the script then exits 1 when a page is out of date.

The `docs` workflow (`.github/workflows/docs.yml`) runs the script with
`--check` on every pull request. The bundle is resolved afresh there, so a
new release of mml, omml, latexmath or unitsml that changes an output makes
the check fail until the pages are regenerated.
